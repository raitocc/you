## 产品介绍

「与你有关」（Related）汇集用户所在同行与圈子中，在用户加入后产生的内容分享动态。用户通过瞬间、时光两类摘要卡片了解新内容，也可以沿着来源进入对应空间。

本文单独描述 Related 的本轮确认方案。相较主 PRD，本方案将展示范围扩展为瞬间与时光，按分享行为保留独立卡片，采用动态发生时间排序，并限定为加入后的新内容。Related 的范围、排序及卡片规则以本文为准。

## 业务术语

| 术语 | 定义 |
| --- | --- |
| 瞬间（Moment） | 用户发布的一条生活记录，包含文字、图片及心情等信息。 |
| 时光（Album） | 用户整理的一组瞬间，可从时光详情分页浏览其中的瞬间。 |
| 同行（Gathering） | 成员围绕一次共同经历分享瞬间的空间。 |
| 圈子（Circle） | 成员持续分享瞬间、时光的空间。 |
| 动态 | 一次将内容关联到同行、分享到圈子的行为所产生的信息流入口。 |
| 来源 | 这条动态对应的同行或圈子，包含空间名称和可点击入口。 |
| 动态发生时间 | 内容关联到同行、分享到圈子实际发生的时间，决定动态流排序。 |
| 记忆时间 | 瞬间记录的经历发生时间，用于内容展示和时光内部排列。 |

## 功能设计

### 【R01】接收相关内容动态

功能说明

同行有瞬间加入、圈子有瞬间或时光分享时，向当时的有效成员投递动态。用户加入空间后开始接收新动态；空间已有的历史内容继续通过同行、圈子本身浏览。

使用者

已登录且属于对应同行、圈子的用户。

触发条件

| 业务行为 | 动态内容 | 来源 |
| --- | --- | --- |
| 发布瞬间时关联同行 | 瞬间摘要 | 对应同行 |
| 将已有瞬间关联到同行 | 瞬间摘要 | 对应同行 |
| 将瞬间分享到圈子 | 瞬间摘要 | 对应圈子 |
| 将时光分享到圈子 | 时光摘要 | 对应圈子 |

用户流程

1. 成员完成上述关联或分享操作。
2. 系统为符合接收范围的成员保存动态入口。
3. 接收者进入或刷新 Related，浏览新增动态。

业务规则

| 规则编号 | 规则名称 | 规则描述 |
| --- | --- | --- |
| R01-BR01 | 接收范围 | 接收者为动态发生时对应空间的有效成员，包含发布者、分享者本人。 |
| R01-BR02 | 历史范围 | 首次加入空间后开始接收该空间的新动态。已有瞬间在其加入后新关联到同行、分享到圈子，属于新动态；历史内容通过空间入口浏览。重新加入的处理见 R02-BR07。 |
| R01-BR03 | 内容类型 | 同行提供瞬间动态，圈子提供瞬间与时光动态。 |
| R01-BR04 | 原内容引用 | 动态保存内容及来源的引用，摘要和详情读取原内容；内容更新后展示最新信息。 |
| R01-BR05 | 重复处理 | 同一次关联或分享即使发生重复请求、重复事件处理，对同一接收者也只产生一条动态。 |
| R01-BR06 | 编辑与再次分享 | 编辑原内容只更新摘要和详情，保持原动态时间；撤回后再次分享产生一条新动态，采用本次分享时间，原撤回动态继续隐藏。 |
| R01-BR07 | 时光内部变化 | 已分享时光新增、移除瞬间时，通过原时光入口查看最新内容，本次变化只更新内容，额外动态省略。 |

验收规则

| 验收编号 | 验收场景 | 预期结果 |
| --- | --- | --- |
| R01-AC01 | 用户加入同行后，成员关联一条瞬间 | 用户收到该瞬间动态，来源为对应同行。 |
| R01-AC02 | 用户加入圈子后，成员分享时光 | 用户收到时光动态，来源为对应圈子。 |
| R01-AC03 | 用户加入已有内容的空间 | Related 保持原有接收范围，空间历史内容通过空间入口浏览。 |
| R01-AC04 | 将去年记录的瞬间在今天分享到圈子 | 当前成员收到一条今天发生的分享动态。 |
| R01-AC05 | 同一次分享被重复处理 | 每个接收者收到一条对应动态。 |
| R01-AC06 | 本人将瞬间或时光分享进圈子 | 本人也收到对应分享动态。 |
| R01-AC07 | 编辑已分享内容，然后撤回并再次分享 | 编辑保持原动态时间；撤回隐藏原动态；再次分享生成采用本次时间的新动态。 |
| R01-AC08 | 已分享时光增删内部瞬间 | 原入口展示更新后的时光内容，动态数量和动态时间保持原值。 |

### 【R02】浏览相关动态流

功能说明

Related 混合展示瞬间与时光摘要，保留来源，按动态发生时间倒序排列。用户通过游标加载更多，返回列表时保留浏览位置。

使用者

已登录用户。

触发条件

进入 Related、主动刷新或加载更多。

用户流程

1. 进入 Related，加载最新一页动态。
2. 浏览内容摘要、作者或所有者、分享者及来源信息。
3. 点击卡片进入内容，点击来源进入对应同行或圈子。
4. 返回列表继续浏览，向下加载更多。

卡片组成

| 信息 | 瞬间卡片 | 时光卡片 |
| --- | --- | --- |
| 内容摘要 | 标题、正文摘要、封面及心情等摘要信息；具体字段沿用瞬间摘要模型 | 时光名称、介绍摘要、封面等摘要信息；具体字段沿用时光摘要模型 |
| 内容归属 | 瞬间作者 | 时光所有者 |
| 动态行为 | 谁将瞬间关联到同行、分享到圈子 | 谁将时光分享到圈子 |
| 来源 | 同行或圈子的名称、入口 | 圈子的名称、入口 |
| 动态时间 | 关联或分享发生的时间 | 分享发生的时间 |

作者与分享者为同一人时，界面可合并展示人物信息。摘要字段可按实际卡片体验调整，内容标识、类型与来源应足以支持准确跳转。

业务规则

| 规则编号 | 规则名称 | 规则描述 |
| --- | --- | --- |
| R02-BR01 | 排序依据 | 按动态发生时间倒序，同一时间按动态 ID 倒序，使用游标分页。 |
| R02-BR02 | 时间含义 | 旧瞬间的新分享排在新动态的位置；记忆时间作为内容信息展示。后台投递延迟沿用业务实际发生时间。 |
| R02-BR03 | 来源保留 | 按分享行为保留独立卡片，每张卡片展示对应来源。同一内容分享进多个空间时分别展示；瞬间与包含该瞬间的时光也各自保留对应分享卡片。后续根据体验反馈评估合并。 |
| R02-BR04 | 空与失败状态 | 空列表引导加入同行、圈子；加载失败提供重试，加载更多失败保留已有列表。 |
| R02-BR05 | 当前可访问性 | 展示及打开时按当前来源和内容权限处理。内容删除、分享撤回、关联取消、退出、被移出或空间解散后，隐藏对应来源的动态。列表先筛选当前有效动态，再按游标分页。 |
| R02-BR06 | 退出记录保留 | 退出空间后保留原投递记录，Related 隐藏该来源的卡片；其他空间产生的独立卡片继续按各自权限展示。 |
| R02-BR07 | 重新加入 | 重新加入后，恢复以前收到过且来源、内容当前仍有效的动态，沿用原动态时间；离开期间发生的动态保持空缺，重新加入后继续接收新动态。 |

验收规则

| 验收编号 | 验收场景 | 预期结果 |
| --- | --- | --- |
| R02-AC01 | 同时收到瞬间与时光分享 | 两类卡片混合排列，来源清楚。 |
| R02-AC02 | 今天分享去年的瞬间 | 按今天的分享时间排列，卡片可展示去年的记忆时间。 |
| R02-AC03 | 后台稍后完成投递 | 按关联或分享实际发生时间排列。 |
| R02-AC04 | 连续加载多页 | 按统一游标顺序衔接；同一次动态保持一条记录。 |
| R02-AC05 | 撤回分享、取消关联或退出空间后刷新 | 对应来源的动态隐藏，分页按其余有效动态连续加载。 |
| R02-AC06 | 同一瞬间分别分享到用户所在的两个圈子 | 展示两张独立卡片，分别指向各自来源；退出其中一个圈子后，仅隐藏该来源卡片。 |
| R02-AC07 | 同时收到瞬间和包含它的时光分享 | 瞬间卡片、时光卡片分别保留。 |
| R02-AC08 | 退出空间后重新加入 | 以前收到且当前仍有效的动态恢复到原排序位置，离开期间的动态保持空缺，加入后的新分享正常接收。 |

### 【R03】打开内容与来源

功能说明

瞬间卡片打开共享瞬间详情；时光卡片打开共享时光详情，再从时光中的瞬间列表进入共享瞬间详情。来源入口始终对应产生这条动态的空间。

使用者

接收到动态、且当前具有对应查看权限的用户。

触发条件

点击卡片或来源。

用户流程

- 瞬间：动态摘要 → 对应来源下的瞬间详情。
- 时光：动态摘要 → 对应圈子下的时光详情与瞬间列表 → 时光内某个瞬间的详情。
- 来源：来源名称 → 对应同行或圈子。

业务规则

| 规则编号 | 规则名称 | 规则描述 |
| --- | --- | --- |
| R03-BR01 | 来源语义 | 共享内容沿对应来源打开，复用同行、圈子的共享查看能力。 |
| R03-BR02 | 时光内容 | 分享时光产生一张时光卡片，其内部瞬间通过时光逐级浏览。 |
| R03-BR03 | 访问失效 | 列表加载后来源或内容失效，点击时提示访问状态变化，并提供返回入口。 |
| R03-BR04 | 返回位置 | 从内容或空间返回时，保留 Related Tab、已加载列表和滚动位置；刷新时更新有效动态。 |

验收规则

| 验收编号 | 验收场景 | 预期结果 |
| --- | --- | --- |
| R03-AC01 | 点击同行瞬间卡片 | 进入该同行中的共享瞬间详情。 |
| R03-AC02 | 点击圈子时光卡片，再点击内部瞬间 | 按圈子共享时光的查看路径逐级打开。 |
| R03-AC03 | 点击来源，再返回 | 进入正确空间，返回后恢复 Related 浏览位置。 |
| R03-AC04 | 卡片展示后分享被撤回 | 打开时提示状态变化，刷新列表移除对应动态。 |

## 本轮取舍与后续范围

| 事项 | 本轮处理 | 后续安排 |
| --- | --- | --- |
| 动态刷新 | 进入 Related、主动刷新及加载更多时查询 | 实时更新放到后续阶段，再确定连接方式与提示交互 |
| 跨来源卡片 | 按分享行为独立展示 | 根据反馈评估来源合并、筛选等优化 |
| 历史内容 | 首次加入只接收加入后的新动态；重新加入恢复以前收到且当前仍有效的记录 | 空间历史内容继续通过同行、圈子入口浏览 |
| 时光内部变化 | 原入口展示最新时光内容 | 本轮只为时光分享行为生成动态 |

## 实现方向参考

现有 `user_inbox` 已包含接收者、来源、内容类型及内容引用，可作为动态存储的基础。采用写时投递方向：业务发布关联、分享等事件，由独立监听处理信箱投递；后续通知、在线推送分别订阅对应事件。动态发生时间与入库时间分开表达。具体表调整、事件模型和接口在后端开发计划中细化。
