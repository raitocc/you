# YOU 后端开发交接

更新日期：2026-11-03。本文基于基础工程提交 `203ca42`，面向第一次接触仓库的开发者。

当前已经完成 Spring Boot 空项目初始化、基础依赖接入、MySQL 与 RustFS 的本地编排、数据库结构设计和 Flyway 初始迁移文件。正式业务接口从这个基础上开始开发。

第一次接手，先读第 1～3 节完成环境接入；开始开发时查第 4～6 节；具体技术用法从第 7 节进入对应教程。

## 1. 产品范围与当前进度

YOU 是个人记忆平台，用户以“瞬间”记录经历，再通过“时光”“同行”和“圈子”整理与分享。

| 业务概念 | 英文名称 | 含义 |
|---|---|---|
| 瞬间 | Moment | 用户发布的文字、图片或图文记录，是内容的基本单位 |
| 时光 | Album | 手动选择或由 AI 一次性整理的瞬间集合 |
| 同行 | Gathering | 围绕一次共同经历建立的成员与记录空间 |
| 圈子 | Circle | 持续分享瞬间、时光及同行入口的成员空间 |

后端第一版采用一个 Spring Boot 单体应用，基础设施为 MySQL 和 RustFS。AI 能力计划随业务接入 Spring AI，目前处于后续开发范围。

当前进度可以按三个层次理解：

| 层次 | 当前状态 |
|---|---|
| 工程基础 | Maven 项目、MVC、接口文档、日志、数据库访问、迁移和对象存储 SDK 已接入 |
| 数据结构 | 14 张业务表已形成设计文档和初始 SQL，交接时尚未执行迁移 |
| 业务实现 | 注册登录、瞬间、时光、同行、圈子、消息及 AI 等待开发 |

## 2. 从空项目到现在完成了什么

### 2.1 建立后端工程与外层 Git 仓库

后端由 IDEA 创建，工程名称为 `you-backend`，启动包为 `com.you.youbackend`。

整个 `YOU` 目录使用一个 Git 仓库，后端子目录作为普通目录管理。根目录 `.gitignore` 已排除 IDE 配置、Maven 构建产物、日志、本地环境文件和容器数据目录。

基础代码、Compose、数据库脚本和技术教程已在 `203ca42` 提交。当前仓库为本地 Git 仓库，远程仓库地址待团队配置。

### 2.2 接入当前使用的技术组件

具体依赖以 `you-backend/pom.xml` 为准：

| 组件 | 当前版本或配置 | 用途 |
|---|---|---|
| Java | 编译目标为 17 | 应用代码与语言级别 |
| Spring Boot | 4.1.2 | 应用启动与自动配置 |
| Spring MVC | `spring-boot-starter-webmvc` | HTTP 接口 |

| MySQL JDBC 驱动 | Spring Boot 管理版本 | 建立数据库连接 |
| Flyway | Boot starter + `flyway-mysql`，Boot 管理版本 | 启动时执行数据库迁移 |

`S3Config` 已将 `S3Client` 注册为 Spring Bean，使用配置文件里的服务地址和凭据。当前正式代码使用者可以直接注入它。

### 2.3 编排本地基础设施

根目录 `compose.yaml` 包含两个服务：

| 服务 | 镜像 | 本机端口 | 数据卷 |
|---|---|---|---|
| MySQL | `mysql:8.4` | 3306 | `mysql_data` |
| RustFS | `rustfs/rustfs:latest` | S3 接口 9000，控制台 9001 | `rustfs_data` |

后端目前由 IDE 或本机 Java 进程运行。Compose 中管理的是这两个基础设施服务。

### 2.4 整理数据库设计与迁移文件

数据库设计覆盖账号、图文记录、集合、成员、分享、信箱和通知。初始迁移为：

文件包含 14 条建表语句，以及主键、唯一索引、基础查询索引和中文注释。完整字段说明见 [数据库设计](数据库设计.md)。

### 2.5 将练习代码集中到测试源码目录

MVC、日志、MyBatis-Plus 和 RustFS 的练习代码保留在 `src/test/java`。正式源码目前只有启动类和 S3 配置类。

## 3. 第一次在自己的电脑上运行

### 3.1 准备 Java、Maven 和 Docker

准备以下工具：

- JDK 17 或 21。项目编译目标和 IDEA 语言级别保持 17，当前编译验证使用 JDK 21。
- Maven 3。当前已验证的版本为 3.9.15；命令行操作需能找到 `mvn`。
- Docker Desktop，使用 Linux 容器。
- IDEA 或其他 Java 开发工具。

在 IDEA 中打开 `YOU` 目录，将 `you-backend/pom.xml` 导入为 Maven 项目，等待依赖同步完成。

本机接入过程中，IDEA 的 Maven 设置曾由 Wrapper 切换为捆绑 Maven 3 后恢复正常。仓库保留的 Wrapper 当前指向 Maven 3.10.0；接手时可先使用已验证的 Maven 3.9.15 或 IDEA 的捆绑 Maven 3。

### 3.2 启动 MySQL 和 RustFS

在 `YOU` 根目录执行：

```powershell
docker compose up -d mysql rustfs
docker compose ps
```

首次使用空数据卷时，MySQL 根据 Compose 配置创建 `you` 数据库和对应账号。当前本机开发配置如下：

| 项目 | 当前配置 |
|---|---|
| MySQL 地址 | `localhost:3306` |
| MySQL 数据库 | `you` |
| MySQL 普通账号 / 密码 | `you` / `you` |
| MySQL root 密码 | `you` |
| RustFS S3 地址 | `http://localhost:9000` |
| RustFS 控制台 | `http://localhost:9001` |
| RustFS Access Key / Secret Key | `you` / `you` |

Compose 将端口绑定到 `127.0.0.1`，用于每位开发者的本机环境。应用配置位于 `you-backend/src/main/resources/application.yaml`，已与上述地址和凭据对齐。

### 3.3 先编译，再确认首次建表

在 `YOU` 根目录执行：

```powershell
mvn -f you-backend/pom.xml -DskipTests clean package
```

这条命令会编译正式源码和测试源码，再生成应用 JAR，测试执行阶段跳过。该操作可验证构建过程，数据库迁移在应用启动阶段执行。

交接时的数据库状态为：练习用 `test` 表已删除，14 张业务表的建表脚本仍待首次执行。先审阅 `V1.0__init_schema.sql`，再进入下一步启动应用。

Spring Boot 启动时，Flyway 会使用应用数据源扫描 `db/migration`，执行待执行脚本，并记录到 `flyway_schema_history`。[Spring Boot 数据库初始化说明](https://docs.spring.io/spring-boot/how-to/data-initialization.html)

### 3.4 启动后端并检查入口

在 IDEA 运行 `YouBackendApplication`，或者在 `YOU` 根目录执行：

```powershell
java -jar you-backend/target/you-backend-0.0.1-SNAPSHOT.jar
```

启动后访问：

| 地址 | 作用 |
|---|---|
| `http://localhost:8080/scalar` | 查看接口文档、发送调试请求 |
| `http://localhost:8080/v3/api-docs` | 查看 OpenAPI JSON 文档 |
| `http://localhost:9001` | 管理 RustFS 存储桶和文件 |

Scalar 和 OpenAPI 文档由当前 starter 提供。[springdoc 接入说明](https://springdoc.org/)

当前正式 Controller 将随业务开发加入；`/test/get`、`/test/post` 是测试源码中的练习接口。正常启动主应用时，Scalar 的业务接口列表会随正式 Controller 的增加而丰富。

首次迁移成功后，可以在数据库工具中检查：

```sql
SHOW TABLES;

SELECT version, description, script, success
FROM flyway_schema_history
ORDER BY installed_rank;
```

预期出现 14 张业务表和 Flyway 历史表，初始脚本的执行记录中 `success` 为 `1`。

### 4.3 理解当前测试的运行条件

`TestRecordMapperTest` 保存了三个方向的练习：数据库连接、`test` 表增删改查，以及 RustFS 上传并读回文件。

- 连接练习使用当前配置中的 MySQL。
- 增删改查练习使用 `test` 表，该表目前已删除；继续做这个练习时，可以按 [数据库连接与实操](数据库连接与实操.md) 准备练习库和表。
- 文件练习使用 RustFS 的 `demo-files` 桶，可以在控制台创建该桶后运行。
- `YouBackendApplicationTests.contextLoads()` 会启动 Spring 上下文，并使用当前数据库和 Flyway 配置。

当前交接版本的验证范围是编译、测试源码编译和打包。数据库迁移、完整测试集和业务流程的运行验证属于后续接入工作。

## 5. 开发时沿用的核心约定

### 5.1 ID、审计时间与逻辑删除

所有业务主键和关联 ID 使用 UUIDv7，数据库类型为 `BINARY(16)`，接口层使用 UUID 字符串。应用负责生成 UUIDv7，并按原始字节顺序转换。

`created_at`、`updated_at` 由应用统一填写 UTC 时间，数据库使用 `DATETIME(3)`。`deleted_at` 为空表示有效，有值表示删除、移出、离开或撤回，具体含义由所在表决定。

这些是当前表结构的约定。UUIDv7 生成与 MyBatis 类型转换、审计字段自动填充、逻辑删除映射仍需在业务代码中接入。

### 5.2 关联、唯一关系与图片顺序

关联关系由应用层校验和事务维护。数据库已建立主键、必要的非空约束和业务唯一索引。

成员、时光内容、标签和圈子分享等唯一关系采用“恢复原行”的方式重新建立：清空 `deleted_at`，更新必要字段。同一瞬间的同一 `file_id` 只保留一条图片关系；重新添加时恢复原行，有效图片的顺序由应用在事务中维护。

登录账号使用默认的大小写不敏感比较规则；RustFS 对象键使用精确比较规则。

### 5.3 原内容与访问范围

瞬间原内容保存一份，时光、同行和圈子使用关联关系组织内容。Yours 查询本人瞬间；Related 查询有效同行内容与圈子直接分享瞬间的并集，并按瞬间去重。搜索范围是两者的并集。

时光分享和同行入口分享按数据库文档中的权限规则读取内容。信箱与通知承载消息入口，实际读取时由业务层判断当前权限。完整规则见 [数据库设计](数据库设计.md)。

### 5.4 媒体文件与对象存储

RustFS 保存实际文件，`media_file` 保存对象键、上传者、类型和大小等元数据。文件上传成功并检查后建立记录；读取时先判断业务访问权限，再生成临时地址。

当前已实现 S3 客户端 Bean。业务存储桶名称、上传接口、文件记录写入和临时访问地址接口将在媒体模块中落实；现有练习桶名为 `demo-files`。

### 5.5 后续数据库变更

初始迁移版本为 `1.0`，后续使用递增版本，例如：

```text
V1.0__init_schema.sql
V1.1__add_some_column.sql
V1.2__add_some_index.sql
```

每次表结构变更新增一个迁移文件。已进入共同开发环境的历史脚本保持原样，后续调整通过新迁移完成。多人同时改表时先协调版本号，再分别编写各自的变更，合并时核对执行顺序。

## 6. 接下来如何开始协作

先共同确认初始表结构并完成首次迁移，再以一条完整的业务流程开始实现。建议先跑通：

```text
注册登录 → 上传图片 → 发布瞬间 → 查询自己的瞬间 → 编辑和删除
```

这个过程会落实用户身份、UUID 转换、审计时间、逻辑删除、媒体存储和接口响应等共同基础。字段与规则以数据库文档和迁移脚本为依据，接口请求与响应格式在编码前由前后端对齐。

共同基础确定后，可以围绕瞬间、时光、同行、圈子和消息分工。业务代码在 `com.you.youbackend` 下按业务逐步建立包结构，测试放入 `src/test/java`，表结构变更放入 `db/migration`。

每次交付说明实现的业务行为、数据库变更和验证结果。当前仓库已经接入 Scalar，新 Controller 的接口说明可以直接随代码维护。
