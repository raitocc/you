# 瞬间与时光后端改动说明

本轮重整了瞬间、时光的读写流程。后端和前端联调时，重点对齐时光内瞬间列表的响应和游标。其余调整主要体现在代码命名、批量处理和注释风格。

## 接口改动

| 接口 | 本轮变化 |
| --- | --- |
| `GET /albums/{albumId}/moments` | 列表项由瞬间详情改为 `MomentSummaryResponse`。卡片使用 `bodyPreview`、`coverUrl` 和 `imageCount`；需要完整正文、组图和标签时再请求瞬间详情。 |
| `GET /albums/{albumId}/moments` 分页 | 按 `memoryTime`、`id` 正序。首屏省略游标；下一页传 `cursor.memoryTime` 和 `cursor.id`，从上一页的 `nextCursor` 取值。 |
| 瞬间、时光详情 | Java 响应类型统一用 `DetailedResponse` 后缀，列表摘要用 `SummaryResponse` 后缀。单纯的 Java 类型改名不影响 JSON 字段名。 |
| `POST /media/uploads/test` | 移除后端代传测试入口。上传仍通过申请签名 URL、客户端直传、查询文件就绪状态完成。 |

瞬间和时光的创建、更新接口目前仍返回详情。前端联调时，先把时光瞬间列表的完整详情解析换成摘要解析，并去掉这个分页请求里的 `cursor.createdAt`。后端的 OpenAPI 参数也要与两字段游标对齐。

## 代码风格

- **主流程从上到下读。** Controller 接收请求并委托 Service。Service 按鉴权、准备数据、读写、组装响应的顺序展开。小方法只抽取有名字、能独立理解的业务步骤。
- **名字写出动作和条件。** Mapper 用 `updateUpdatedAtById`、`softDeleteByAlbumIdAndMomentIdIn` 这类名称。Service 用 `validateOwnedMoments` 表达业务意图，由瞬间模块自己完成归属校验。
- **注释讲规则和理由。** JavaDoc 交代用途、前置条件和返回语义。方法体注释写关键步骤，例如「批量插入或恢复关联，保留原关联的创建时间」。普通赋值由变量和方法名表达。
- **分页先截页，再补数据。** 多查一条判断 `hasMore`，只给实际返回的一页批量查计数、作者或封面。无匹配的计数补 `0`，下一页游标取实际返回的最后一条。

## 联调前对齐事项

- 删除瞬间时同步清理 `album_moment` 仍是待办。当前时光计数依赖有效关联，清理完成后，用同一瞬间关联两个时光再删除来验证两边的数量和列表一致。
- 时间统一为 `Instant` 的方案见 [时间统一改造说明](时间统一改造说明.md)。通用约定见 [YOU 后端开发约定](YOU-后端开发约定.md)。
