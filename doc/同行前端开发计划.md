# 同行前端开发计划

## 开发范围与节奏

基于 `YOU-PRD.md`、Apifox 一期接口及现有 Flutter 项目开发同行模块。业务取舍采用后来确认的一期规则。每批接入 2～4 个接口，完成可运行的功能后交给用户审查，审查通过再开始下一批。

一期围绕创建、加入、共同记录与浏览展开。创建者负责编辑、结束和解散；普通成员可以加入、浏览、关联本人瞬间和主动退出。管理权转交、移除成员和 AI 能力列入后续范围。

## 代码职责

沿用 Riverpod、Repository、Dio 和 go_router，以及现有视觉样式与通用组件。

| 位置 | 职责 |
| --- | --- |
| `models/` | 同行、摘要、游标和页面所需的明确类型 |
| `data/remote/` | HTTP 路径、参数和请求 |
| `data/mappers/` | JSON 与模型转换 |
| `data/gathering_repository.dart` | 提供同行数据操作，协调数据来源 |
| `presentation/viewmodels/` | 按列表、编辑、加入等场景管理加载、提交、分页和状态 |
| `presentation/pages/` | 页面布局、输入与导航 |
| `presentation/widgets/` | 有复用价值或可独立理解的界面组件 |

页面调用 ViewModel，ViewModel 调用 Repository，Repository 委托 Remote 请求后端。公共方法表达主流程，辅助方法承担清晰的步骤；方法和组件拆分以减少阅读负担为准。模型转换与请求过程分别组织，避免长链条、深层嵌套和包揽整个模块的类。

复用统一认证、错误提示、用户资料、瞬间展示及分页能力。加载失败保留已有内容，提交失败保留输入；成功后刷新受影响的列表、详情及统计。后端缺失字段在对应代码处记录 TODO，前端保留明确的接入位置，实际展示以服务端已返回的数据为准。

## 分批实施

以下 `{id}` 为同行 ID。每批列出的数量为新增同行接口，已接入的接口按需复用。

### 第 1 批：创建、列表与详情（3 个接口）

当前进度：已完成，用户操作测试通过。

- `GET /gatherings`：本人同行列表，支持下拉刷新、游标分页、加载与错误状态。
- `POST /gatherings`：填写名称、介绍创建同行，成功进入详情。
- `GET /gatherings/{id}`：展示名称、完整介绍、创建者、成员数和瞬间数。

验收：创建后能在列表看到同行，点击卡片可以打开详情。

### 第 2 批：编辑信息与成员列表（2 个接口）

当前进度：用户验收通过，已补测多人资料、编辑权限和跨账号刷新。

- `PUT /gatherings/{id}`：创建者全量保存名称、介绍；介绍传 null 表示清空。
- `GET /gatherings/{id}/members`：分页展示成员公开资料。

验收：编辑后列表与详情保持一致，成员列表可正常浏览。公开资料为空时沿用已约定的空值展示方式。

### 第 3 批：邀请码与扫码加入（2 个接口）

当前进度：用户验收通过，邀请码与扫码加入已完成两台设备联调。

- `GET /gatherings/join-preview`：通过邀请码预览目标，已是成员时提供进入入口。
- `POST /gatherings/join`：确认加入后进入详情，刷新本人同行列表。

客户端展示、复制邀请码并生成二维码；二维码内容直接采用邀请码。手动输入与扫码共用预览和确认流程，修改输入后清除旧预览。加入成功刷新本人列表、详情及成员列表；已有成员直接进入。

采用 `qr_flutter` 展示二维码、`mobile_scanner` 调用相机。新增原生插件后，在 IDEA 停止应用并重新运行；相机授权及实际识别由真机测试。入口为同行首页「加入同行」和详情「邀请同行」。

验收：两个账号完成创建、邀请、预览和加入。

### 第 4 批：浏览共同记录（2 个接口）

当前进度：用户验收通过。

- `GET /gatherings/{id}/moments`：游标分页浏览摘要，展示作者及相关内容。
- `GET /gatherings/{id}/moments/{momentId}`：查看共享瞬间完整内容。

复用瞬间展示组件，按访问场景加载详情，区分本人和他人内容的操作入口。列表顺序沿用后端返回结果。

验收：加入者能浏览其他成员关联的瞬间并打开详情。

### 第 5 批：关联、移出与发布联动（2 个接口）

当前进度：用户验收通过。

- `POST /gatherings/{id}/moments`：批量关联本人瞬间。
- `POST /gatherings/{id}/moments/remove`：批量移出本人瞬间。

复用本人瞬间列表实现多选；关联其他同行导致整批失败时展示提示并保留选择，已关联本同行按成功处理。移出保留原瞬间。成功后刷新内容、统计及相关瞬间状态。

联动现有发布接口：发布页从本人同行列表选择目标，提交 `gatheringId`，保存草稿和发布重试均保留所选目标。活动代码统一采用 `gatheringId`，读取旧本地草稿时保留 `journeyId` 字段迁移。已有瞬间详情的「关联同行」入口复用批量关联接口，正文编辑接口继续只修改内容。

验收：已有瞬间能添加、移出，新瞬间可以在发布时关联同行。

### 第 6 批：退出、结束与解散（3 个接口）

当前进度：用户验收通过。

- `POST /gatherings/{id}/leave`：普通成员退出，解除本人瞬间关联，保留原始记录。
- `POST /gatherings/{id}/end`：创建者结束同行；已有成员可继续浏览、退出和移出瞬间，停止新成员加入与新增关联。
- `DELETE /gatherings/{id}`：创建者解散，解除全部同行瞬间关联，保留原始记录。

详情右上角「同行操作」按身份展示入口，执行前确认影响，提交中锁定操作，失败提示并保留页面。创建者通过解散离开同行。

后端列表摘要和详情统一返回 status（ONGOING / ENDED），创建、修改及加入响应一起带上。结束成功后刷新列表、详情和内容；已结束同行展示状态，收起结束、邀请和新增关联入口，选择同行时禁用已结束项。直接打开邀请或添加页也展示结束提示，浏览、移出和普通成员退出继续可用。

验收：分别使用创建者和普通成员账号走通操作，退出或解散后返回列表。

### 第 7 批：面对面加入（3 个接口）

当前进度：用户验收通过，一期同行功能闭环。同行、面对面、瞬间及定位异常共 43 项测试、静态分析和 Android 调试包构建通过。

- `POST /gatherings/{id}/face-to-face`：创建者开启四位数字短码，保留前导零。
- `GET /gatherings/face-to-face/join-preview`：按短码和位置查找 100 米内候选，展示全部匹配。
- `POST /gatherings/face-to-face/join`：选择目标后提交同行 ID 和短码确认加入。

入口为同行首页「面对面」，先选择「发起同行」或「加入同行」。

发起分两步填写：名称、介绍 → 四位数字短码。点击「下一步」只保存表单输入，返回时保留已填信息。点击「确认发起」后获取定位，依次创建同行、开启短码，成功直接进入同行详情。定位失败时保留表单；创建成功但开启失败时，重试沿用同一条同行记录。

加入直接输入短码，定位后展示附近全部候选，由用户确认目标；已有成员可直接进入。每个同行只允许成功开启一次，短码在同行创建后 10 分钟截止。候选卡片使用服务端 expiresAt 判断有效期。

定位采用 [geolocator](https://pub.dev/packages/geolocator) 单次前台定位，已配置 Android 和 iOS 使用说明；拒绝授权、系统定位关闭和超时均显示提示。

验收：两台附近设备完成面对面创建与加入，定位授权、空候选及过期提示可用。

## 第 4、5 批验收清单

两台设备分别登录账号 A、B，加入同一个同行；双方各准备文字、多图瞬间。热重启或重新运行应用后测试。

| 场景 | 操作与预期 |
| --- | --- |
| 共同浏览 | 双方从详情进入「浏览共同记录」，看到作者、摘要、封面，按发生时间正序展示；打开详情可读完整正文和组图 |
| 批量添加 | 从详情「添加本人瞬间」或共同记录页菜单进入，多选后添加，列表和数量刷新；重复添加保持一条关联 |
| 关联冲突 | 同时选择已关联其他同行的记录和一条私人记录提交，整批失败并保留选择；私人记录保持原状 |
| 批量移出 | 共同记录页菜单选择「移出本人瞬间」；他人记录保留展示且不可选，确认后自己的记录从同行移出，在本人瞬间流中继续存在 |
| 发布联动 | 全局加号发布，选择同行后发布；另一账号刷新共同记录可见。再选「不关联同行」发布，保留为个人记录 |
| 详情权限与同步 | 他人共享详情只读；本人共享详情可进入本人详情编辑。修改正文、图片或删除后，相关页面刷新显示最新结果 |
| 分页及失败重试 | 数据超过单页后验证共同记录加载更多、多选跨页保留；请求失败后保留已有页和选择，可继续重试 |

第 2、3 批的跨账号资料、编辑权限及加入流程已通过用户验收；成员分页在人数超过单页上限后补测。

## 第 6 批验收清单

重启后端并重新运行前端。账号 A 创建同行，账号 B 加入，双方各关联一条瞬间；退出、结束、解散分别准备同行测试。

| 场景 | 操作与预期 |
| --- | --- |
| 身份与取消 | 详情右上角「同行操作」：A 显示结束、解散，B 显示退出；先点取消，列表、成员和瞬间关联保持原状 |
| 普通成员退出 | B 确认退出后回到列表，该同行消失；A 刷新成员与共同记录后，B 的成员关系和关联记录消失，B 的个人瞬间与图片仍在 |
| 创建者结束 | A 确认结束，列表与详情显示已结束，邀请、添加和结束入口收起；发布和已有瞬间的同行选择页中，该同行禁用 |
| 结束后的访问 | A、B 仍可浏览成员、共同记录和详情，编辑同行信息、移出本人瞬间；B 仍可退出。第三账号使用原邀请码加入时得到关闭提示 |
| 创建者解散 | A 确认解散后回到列表，双方刷新后同行消失；原详情访问收到失效提示；双方个人瞬间与图片仍在，记录可关联另一个同行 |
| 请求失败 | 断开网络后操作，展示错误并留在详情；恢复连接后可重试，提交期间操作按钮锁定 |

## 第 7 批验收清单

新增定位原生插件后，在 IDEA 停止应用并重新运行，安装包含原生插件和权限的新 APK。后端与 Redis 保持运行。两个设备使用不同账号，授权精确定位；模拟器在扩展控制面板的 Location 中设置到真机附近 100 米内。

| 场景 | 操作与预期 |
| --- | --- |
| 发起 | A 从「面对面 → 发起同行」填写名称、介绍，下一步输入 0005，确认后定位、创建并开启，成功直接进入同行详情 |
| 返回修改 | 输入短码后返回上一步，名称、介绍保留；再次下一步时短码保留，确认前服务端保持原状 |
| 附近加入 | B 从「面对面 → 加入同行」直接输入 0005 查找，看见同行名、创建者、摘要、距离；确认后进入详情，列表与成员刷新 |
| 多个候选 | 在同一地点用相同短码发起另一同行，查询展示全部候选；分别确认自己选择的目标 |
| 已有成员 | B 再次查询相同短码，候选显示「进入同行」，直接进入已有同行 |
| 修改与空结果 | 修改短码后旧候选消失；输入附近无人使用的短码，显示空结果提示；移到 100 米外再查询时目标消失 |
| 定位失败 | 拒绝授权、关闭系统定位或触发定位超时，显示对应提示；永久拒绝时提供应用设置入口，恢复后可重试 |
| 截止时间 | 有效期按同行创建时间计算；到期后加入按钮停用，重新查询目标消失；创建超过 10 分钟时后端拒绝首次开启 |
| 业务与网络失败 | 断网或目标结束后查询、确认，显示错误；恢复网络可重试，开启失败时已创建的同行仍在列表 |

## 定位插件排查记录

模拟器曾保留添加定位插件前的旧 APK，更新后的 Dart 调用原生定位时抛出 MissingPluginException，流程在发请求前失败。已覆盖安装新 APK，模拟器日志确认 Geolocator 加载并连接定位服务。定位入口现有 started、succeeded、failed 日志，插件缺失时显示完整重新运行的提示。

自动化流程测试使用模拟接口及定位数据；新增回归测试覆盖原生通道缺失的错误转换。两台设备的定位、真实后端创建及加入按本节验收清单验证。

同行状态已在第 6 批接通。面对面采用开启成功直接进入详情的流程，已移除之前的短码回显 TODO。邀请码重置沿用现有后端 TODO，后续单独安排。
