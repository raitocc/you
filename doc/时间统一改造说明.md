# 时间统一改造说明

本文面向后端开发，说明时间字段"请求 → 业务 → 入库全链路 Instant"改造的目标、方案、步骤和验证方法。改造范围是 moment、album、media 三个模块；circle、gathering、inbox 的时间字段随各自重写处理，本文不展开。读者凭本文即可独立完成改造，无须参考其他讨论记录。

## 现状与目标

当前时间处理有三类重复：

| 重复点 | 现状 |
| --- | --- |
| 入库换算 | `MomentService.toDatabaseMemoryTime` 与 `AlbumService.toCursorTime` 两份手写转换，circle 内联第三份 |
| 游标时间类型 | `AlbumListCursor` 用 Instant，`RelatedFeedCursor` 用 LocalDateTime，换算口径不一 |
| 审计时间取值 | `LocalDateTime.now(ZoneOffset.UTC).truncatedTo(ChronoUnit.MILLIS)` 散布 20 余处 |

改造目标：时间在请求 DTO、业务实体、响应、游标中一律使用 `Instant`；Instant 与数据库列的换算收敛到一个 MyBatis 类型处理器（TypeHandler）；审计时间取值收敛到 common 里的一个工具方法。完成后删除两份手写换算，审计取值从 20 余处收敛为一处。

## 关键决策与理由

**数据库列保持 `DATETIME(3)`，不改用 `TIMESTAMP`。** MySQL 的 `TIMESTAMP` 范围是 1970–2038 年，而瞬间的"发生时间"（`memory_time`）允许记录早于 1970 年的回忆，现有代码校验年份 1000～9999 正是为 `DATETIME` 范围而设。存量数据按 UTC 语义读写，无须迁移。

**Instant 与 `DATETIME` 的换算收进全局 TypeHandler。** 类比已有的 `UuidTypeHandler`：写入时 `LocalDateTime.ofInstant(instant, ZoneOffset.UTC)`，读出时 `instant` 由 `LocalDateTime.toInstant(ZoneOffset.UTC)` 得到。注册全局后，实体字段映射和 SQL 参数（`#{...}`）自动走处理器，service 层不再手写换算。

**年份范围校验放在请求入口（service / DTO），不下放到 TypeHandler。** TypeHandler 中抛出的异常会被 MyBatis 包装为 `PersistenceException`，全局异常处理器接不住，参数错误会变成 500。"发生时间超出可保存范围"的校验保留在创建、修改瞬间的入口路径上。

**审计时间统一截断到毫秒。** `DATETIME(3)` 只保留毫秒精度；取值时截断（`truncatedTo(ChronoUnit.MILLIS)`），创建响应回显的时间才与再次读出的一致。

## 改造步骤

按顺序执行，每步完成后编译通过再进行下一步。

### 1. 新增 InstantTypeHandler

位置 `common/mybatis/InstantTypeHandler.java`，参照 `UuidTypeHandler` 的注册方式（`application.yaml` 中 MyBatis 类型映射配置）：

```java
/** Instant 与 DATETIME(3) 列的 UTC 毫秒换算，注册为全局类型映射。 */
public class InstantTypeHandler extends BaseTypeHandler<Instant> {
    // setNonNullParameter：LocalDateTime.ofInstant(parameter, ZoneOffset.UTC) 后交给 PreparedStatement
    // getNullableResult：查询结果按 LocalDateTime 读出，再 toInstant(ZoneOffset.UTC)
    // 四个方法的换算逻辑相同，换算统一带 ChronoUnit.MILLIS 截断
}
```

注册生效后，字段类型为 `Instant` 的实体属性和 SQL 参数自动经过该处理器。

### 2. 新增审计时间工具

位置 `common/util/TimeUtil.java`：

```java
/** 取当前 UTC 时间，毫秒精度，供审计字段（createdAt、updatedAt、deletedAt）统一使用。 */
public static Instant now() {
    return Instant.now().truncatedTo(ChronoUnit.MILLIS);
}
```

命名保持中性：删除场景取到的时间写入 `deletedAt`，同一方法服务所有审计字段。

### 3. 实体时间字段改为 Instant

只改三个模块的实体，其他模块的实体保持现状，等各自模块处理时再迁：

| 实体 | 涉及字段 |
| --- | --- |
| `Moment` | `memoryTime`、`createdAt`、`updatedAt`、`deletedAt` |
| `MomentImage`、`MomentTag` | `createdAt`、`updatedAt`、`deletedAt` |
| `Album` | `createdAt`、`updatedAt`、`deletedAt` |
| `AlbumMoment` | `createdAt`、`updatedAt`、`deletedAt` |
| `MediaFile` | `createdAt`、`updatedAt`、`deletedAt` |

实体是跨模块共享的：circle、gathering 中凡读写这些字段的代码会出现编译报错，按提示把 `LocalDateTime` 改为 `Instant`、删除调用点上的 `.toInstant(ZoneOffset.UTC)` 与 `LocalDateTime.ofInstant(...)` 即可，属于机械修复，不涉及业务判断。

### 4. 删除手写换算，游标直传

- 删除 `MomentService.toDatabaseMemoryTime`、`AlbumService.toCursorTime`；调用点改为直接把 `Instant` 传给 Mapper（换算由 TypeHandler 完成）。
- 游标结构中的时间已统一为 Instant（`MomentFeedCursor.memoryTime`、`AlbumListCursor.createdAt`、`AlbumMomentCursor.memoryTime`），本次仅删除调用点的换算，结构不变。`RelatedFeedCursor.sharedAt` 仍为 LocalDateTime，随信箱模块重写处理。
- Mapper 方法签名中表示时间的参数（如 `selectFeedAfterCursor` 的 `cursorTime`、`selectPageAfterCursor` 的 `cursorTime`）改为 `Instant`。

### 5. 审计取值替换为 TimeUtil.now()

moment、album、media 三模块内所有 `LocalDateTime.now(ZoneOffset.UTC).truncatedTo(...)` 调用替换为 `TimeUtil.now()`，约 10 处。circle、gathering、user 中的调用保持现状，随各自模块迁移。

### 6. 范围校验归位

创建、修改瞬间入口保留"发生时间超出可保存范围"（年份 1000～9999）的参数校验，校验对象是进入实体前的 `Instant`。实现上可把年份判断收敛为一个私有方法，与 TypeHandler 的换算规则保持一致。

## 验证清单

改造完成后逐项验证：

1. 创建、修改瞬间：`memoryTime` 的响应值与入库值一致（毫秒精度），传入带时区偏移的时间，入库按 UTC 正确换算。
2. 分页翻页：本人瞬间流、时光列表、时光内瞬间三条分页的首屏、中间页、末页正常；构造 `memoryTime`（或 `createdAt`）相同的多条记录，确认游标翻页不重不漏。
3. 删除幂等：删除瞬间、删除时光后 `deletedAt` 正确写入，重复删除直接成功。
4. 超范围时间：提交年份超出 1000～9999 的发生时间，返回 400 参数错误而非 500。
5. 媒体链路：上传登记、就绪查询的审计时间正常。
6. `application.yaml` 的逻辑删除配置：确认软删除时间由 Java 侧显式写入的路径（当前全部软删走显式 `set`）不受类型变化影响。

## 范围外挂账

以下事项与本次改造无关，记录备查：`registerFile` 对非 UUID 对象键会抛异常导致消息反复入队；上传被拒（超限、类型不合）的对象在 RustFS 无清理归属；`MomentService`、`AlbumService` 中断言提示文案与断言语义不符；`MediaController` 的 `@PathVariable` 冗余名称及遗留 todo 注释。
