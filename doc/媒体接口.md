## 接口规范

### 基础配置

```
Base URL: http://localhost:8080
API Version: v1
API Prefix: /
```

版本为契约版本，不加入 URL；部署环境使用 HTTPS，替换 Base URL，保留相对路径。

约定不同业务模块前缀：

- 用户：`user`
- 瞬间：`moment`
- 时光：`album`
- 同行：`gathering`
- 圈子：`circle`
- 消息：`message`
- AI：`ai`

### 接口风格

采用 RESTful 风格，使用名词表示资源，示例：

| 操作 | HTTP Method | URL 示例 |
| --- | --- | --- |
| 创建用户 | POST | `/user/users` |
| 创建登录会话 | POST | `/user/sessions` |
| 查询当前用户 | GET | `/user/users/me` |
| 部分更新瞬间 | PATCH | `/moment/moments/{momentId}` |
| 替换可见范围 | PUT | `/moment/moments/{momentId}/visibility` |
| 删除瞬间 | DELETE | `/moment/moments/{momentId}` |

### 数据格式

- JSON 使用 UTF-8、camelCase，`Content-Type: application/json`。
- 文件上传使用 `multipart/form-data`，媒体内容以二进制返回。
- JSON 写入请求体最大 **1 MiB**；图片大小限制由上传接口定义。
- 参数位置明确标注 `Header`、`Path`、`Query`，其余默认为 `Body`。

### 响应与错误处理

- 成功响应：`{code: "SUCCESS", message, data}`；创建用户、瞬间、文件返回 **201**，其他成功返回 **200**。
- 错误响应：`{code, message, data: null}`；可附 `errors: [{field, reason, targetId}]`，无目标时 `targetId=null`。
- 错误响应不得暴露堆栈、数据库等内部信息。

### 时间规范

- 响应时间统一为 **UTC 毫秒精度**，格式：`2026-11-03T02:00:00.000Z`。
- 输入时间必须包含时区，服务端统一转换为 UTC。
- 时间区间采用 **左闭右开** `**[start, end)**`。
- 记忆时间未传时默认为当前时刻；客户端按用户时区展示及选择日期。

### 认证与授权

使用 JWT Bearer Token，示例：

```
GET /user/users/me
Authorization: Bearer eyJhbGciOi...
```

- 注册、登录公开；其他接口需要 JWT。
- 令牌固定有效期 7 天（604800 秒），无刷新接口，到期重新登录。
- 验证签名、有效期、签发者和受众；服务端仅接受固定配置的签名算法。

## POST 申请图片上传

POST /media/uploads

POST `/media/uploads` · JWT Bearer Token

为头像或瞬间图片申请统一上传凭据，成功返回 201。请求体必填 mimeType、byteSize：支持 image/jpeg、image/png、image/webp，大小 1～10485760 字节（10 MiB）。

#### 上传流程

1. 提交图片的 MIME 类型和字节数，取得 uploadId、uploadUrl、method、headers、expiresAt。
2. 使用返回的 PUT 地址和 headers，直接向 RustFS 上传文件二进制。该请求使用预签名鉴权，客户端的应用 Authorization 仅用于业务 API。
3. 调用 POST /media/uploads/{uploadId}/complete 确认文件，取得 fileId。
4. 将 fileId 用于用户资料的 avatarFileId 或瞬间的 imageFileIds。

```json
{"mimeType":"image/jpeg","byteSize":204800}
```

#### 上传凭据

uploadId 绑定当前登录用户、临时存储键、声明大小与类型，凭据有效期为 10 分钟。临时凭据由服务端维护，数据库沿用 media_file；确认成功时创建文件记录。存储键由服务端生成。预签名 PUT 在有效期内可以重复使用，因此上传位置为临时对象，确认时复制到服务端控制的最终对象键。

实际文件类型、大小和图片解码结果在确认上传时校验。成功申请仅表示获得上传凭据，业务绑定使用确认后返回的 fileId。

> Body 请求参数

```json
{
  "mimeType": "image/jpeg",
  "byteSize": 204800
}
```

## POST 确认图片上传

POST /media/uploads/{uploadId}/complete

POST `/media/uploads/{uploadId}/complete` · JWT Bearer Token

确认当前用户已上传的图片，成功返回 200。路径参数 uploadId 来自申请上传接口，请求体为空。

#### 确认流程

1. 校验上传凭据属于当前用户且处于有效期内。
2. 对临时文件生成服务端控制的最终对象快照，针对该最终对象校验实际类型、字节数和图片解码结果；支持 JPEG、PNG、WebP，最大 10 MiB、4000 万像素。
3. 校验通过后创建 media_file，owner_user_id 来自 JWT sub，保存最终 storage_key、mime_type、byte_size，返回 fileId、mimeType、byteSize。
4. 保存该 uploadId 的确认结果，重复或并发确认返回同一个 fileId。已成功确认的结果在上传凭据保留期间可查询；超期未确认返回 410，客户端重新申请上传。

最终对象通过独立存储键保存，旧的 PUT 地址只能修改临时对象。校验和入库针对同一最终对象执行，后续 PUT 重传不会改变已确认的文件内容。

#### 后续使用

- 修改头像：PUT /user/users/me 提交 avatarFileId。
- 发布或编辑瞬间：提交 imageFileIds。
- 图片访问分别由 user 和 moment 模块依据业务对象鉴权。发布前可以使用客户端本地图片预览。

用户资料或瞬间保存失败时，文件保留为未绑定资源，由后续清理按有效业务引用处理。

## 已确认的持久化与保留规则

上传凭据及确认结果持久化在新增的 `media_upload` 表，服务重启后仍可重复确认。确认结果从成功确认时起保留 24 小时，期间重复或并发确认返回同一 fileId，不受原 PUT 凭据到期影响。未确认凭据过期后返回 410，并额外保留 24 小时供客户端识别过期状态；超过保留时间统一返回 404。清理凭据不会删除已确认的媒体文件，文件回收另按有效业务引用处理。
