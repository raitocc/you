# 「与你有关」后端手写清单

需求见 [「与你有关」PRD](YOU-与你有关-PRD.md)。练习分支不包含动态流实现；同行关联、圈子分享和共享详情仍是原有业务。请用新的本地 MySQL schema：练习分支的 Flyway 初始迁移移除了信箱表，不能复用已执行旧迁移的 schema。

1. **先建表和 Mapper。** 新增 Flyway 迁移、`UserInbox`、来源和内容类型枚举、`UserInboxMapper`。每个接收者一行，UUIDv7 做主键；内容、来源和圈子分享用 ID 引用。列表按接收者、失效时间、分享时间和 ID 建组合索引，撤回按分享或来源定位。保留可空的 `read_at`，这次不做已读。
2. **跑通写入。** 先做「瞬间关联到同行」这一条：在现有事务内发布事件，由同步监听器调用 `InboxService`。取操作发生时的有效成员（含本人），批量写入；监听写入失败时业务一起回滚。再接上创建瞬间时附带关联、圈子瞬间和时光分享；只对实际新增或恢复的关系投递，重复操作和后来加入的人不补发。
3. **补齐失效。** 同行解除关联、圈子撤回、成员退出或被移除时发布对应事件。按来源和内容、圈子分享 ID，或来源和操作者标记受影响的投递。读取时仍判断接收者是否在该空间、来源和原内容是否有效。
4. **跑通读取。** 建 `RelatedController`、`RelatedService`、游标和响应 DTO。用登录用户 ID 查信箱，分别校验同行瞬间、圈子瞬间和圈子时光，在分页前过滤不可见记录。三路合并后按 `shared_at DESC, id DESC` 取 `limit + 1`，批量补当前页的内容、作者和来源摘要。同一内容来自两个空间时分开返回。
5. **验收。** 先验证一次分享给多人、重复分享不多投，接着验证晚加入、撤回、退圈和同毫秒跨页。后端跑通后，如需在 App 联调，再接回「与你有关」页签的请求和卡片。
